# 接入一个新的比赛平台

sapper 的「平台」只是 5 个方法的适配器。除了 `lib/arena.py`（腾讯 TSecBench）之外，
一切（事实图谱、auto 循环、控制台、报告导出）都是通用的。

## 三种接入方式（从省事到彻底）

| 方式 | 适用场景 | 要做什么 | 工作量 |
|---|---|---|---|
| **A. 手工模式** | 平台没有 API，或只给 Web 界面 | 用控制台「开始 → 渗透测试/其他任务」为每道题建任务，flag 手动复制到平台 | 0 代码 |
| **B. 本地离线** | 组委会把题目和 flag 以文件形式发给你 | 写一个 `arena.json`（provider=local）+ 题目列表 | 5 分钟，无代码 |
| **C. 平台适配器** | 平台有 HTTP API（CTFd、自研等） | 加一个 `lib/arena_<名字>.py`，实现 5 个方法 | ~100 行 |

## B. 本地离线（provider=local）

在**任务根目录**下建 `.sapper/arena.json`：

```json
{
  "provider": "local",
  "challenges": [
    {
      "unique_code": "q1",
      "description": "公司官网存在 SQL 注入，请拿到管理员 flag",
      "target": "10.0.0.5:8080",
      "flag": "flag{example}",
      "score": 100,
      "difficulty": "easy",
      "hint": "先看 login.php"
    }
  ]
}
```

然后正常开跑：`sapper bench --root <该目录> ...` 或在控制台「⚡ 跑分」里把平台类型选成
「本地离线」、任务根填新名字（控制台会自动写这个文件，token 可留空）。

计分进度存在 `.sapper/local_state.json`，重启不会重复提交。
`flag` 与 `flag_sha256` 二选一——不想把明文写在配置里就用哈希。

## C. 平台适配器（推荐给有 API 的平台）

在 `lib/` 下新建 `arena_<provider>.py`，暴露一个 `ArenaClient` 类，实现：

```python
class ArenaClient:
    @classmethod
    def load(cls, store_root: Path) -> "ArenaClient": ...   # 读 <root>/arena.json
    @classmethod
    def config_path(cls, store_root: Path | None = None) -> Path: ...
    @classmethod
    def write_template(cls, store_root: Path) -> Path: ...   # 可选，写配置模板
    def list_challenges(self) -> list[dict]: ...
    def start_challenge(self, unique_code: str) -> dict: ...
    def get_hint(self, unique_code: str) -> dict: ...
    def submit_flag(self, unique_code: str, flag: str) -> dict: ...
    def close_challenge(self, unique_code: str) -> dict: ...
```

字段契约（bench / 控制台都依赖它）：

```python
list_challenges() -> [{
    "unique_code": "q1",          # 必填，唯一
    "description": "...",         # 题目描述（会写进作战图）
    "difficulty": "easy|medium|hard",
    "total_score": 100,
    "flag_count": 1,
    "correct_flag_count": 0,
    "is_completed": False,        # 已通关的会被 bench 跳过
    "container_status": "available|stopped",
    "container_addr": ["10.0.0.5:8080"],   # 靶标地址，auto 用它攻击
}]

start_challenge(code) -> {"unique_code": code, "container_addr": ["..."]}
submit_flag(code, flag) -> {
    "correct": True/False,
    "awarded": 100, "cumulative_score": 100,
    "correct_flag_count": 1, "total_flag_count": 1,
}
close_challenge(code) -> {"unique_code": code, "closed": True}
```

错误约定：抛 `ArenaError`（本模块内定义）；`code="duplicate"` 表示重复提交，
`code="invalid_state"` + message 含 `max active` 表示并发容器到上限。

启用方式（二选一）：

1. `arena.json` 写 `{"provider": "你的名字", "base_url": "...", "token": "..."}`
2. 环境变量 `SAPPER_ARENA_PROVIDER=你的名字`

已内置参考实现：

- `lib/arena.py` —— 腾讯 TSecBench（`/openapi/v1/challenges`，BENCHMARK_TOKEN 头）
- `lib/arena_ctfd.py` —— CTFd（`/api/v1/challenges`，`Authorization: Token`，attempt 提交）
- `lib/arena_local.py` —— 本地离线（文件计分，可离线自测）

## 控制台里怎么用

「⚡ 跑分 → 启动新跑分」有「比赛平台」下拉：

- **腾讯 TSecBench**：用「设置 → 任务凭证」里保存的 token
- **CTFd**：填平台地址 + CTFd 访问令牌（Settings → Access Tokens）
- **本地离线**：填任务根名即可，token 可留空；随后手动补 `arena.json` 的 challenges

## 自测方法（不花钱、不连平台）

`lib/arena_local.py` 就是为了这个：给它一个 challenges.json + 一个假引擎
（`SAPPER_BIN` 指向你的桩脚本），跑 `sapper bench` 就能验证
「开题 → 建图 → 解题 → 提交 → 计分 → 下一题」的整条链路。
