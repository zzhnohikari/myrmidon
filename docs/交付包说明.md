## 二、部署（三步）

### 前置条件

- Linux x86_64（Ubuntu 22.04 实测），**2 核 4G 起**
- Docker 20.10+（`docker info` 能正常返回）
- 若要用 `compose.yml` 方式启动，还需 compose 插件：Ubuntu 上 `apt install docker-compose-v2`
  （`deploy.sh` 不依赖 compose，没装也能正常部署）
- 磁盘 ≥ 20G（镜像解压约 1.3G，其余是任务数据）

### 第 1 步：校验完整性（建议）

```bash
sha256sum -c SHA256SUMS
```

### 第 2 步：一键部署

```bash
chmod +x deploy.sh
./deploy.sh
```

脚本会依次完成：导入镜像 → 创建管理员账号（可交互设密码，或随机生成）→ 启动容器 → 健康检查 → 鉴权自检，最后打印访问地址与账号。

### 第 3 步：登录配置

浏览器打开 **http://127.0.0.1:8890**，用脚本给出的账号登录，然后：

1. 「设置 → 模型网关」填 Base URL 与 Token，点「拉取模型」选择模型
2. 「设置 → 执行默认参数」设定默认预算（分钟）、步数、默认模型
3. 新建任务 → 输入目标 → 开始执行

> 模型网关也可以提前写进同目录的 `.env`（参考 `.env.example`），或写成 `model.env`（仅含 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 两行），脚本会自动加载。

## 三、验证部署是否正常

```bash
# 1. 容器状态，应为 Up (healthy)
docker ps --filter name=myrmidon

# 2. 健康检查，应为 {"ok": true, ...}
curl -s --noproxy '*' http://127.0.0.1:8890/api/health

# 3. 未登录访问接口，应为 401（返回 200 说明鉴权没生效）
curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8890/api/missions
```

三条都对上，说明部署完成。第 3 条最关键——本次交付曾出现过"账号建了但控制台仍是开放模式"的缺陷，已修复，用这条可以立刻发现类似问题。

## 四、日常运维

```bash
docker stop myrmidon          # 停止
docker start myrmidon         # 启动
docker logs -f --tail 200 myrmidon   # 看日志

# 备份（数据全在 data/，容器本身无状态）
tar czf backup-$(date +%F).tar.gz data/

# 恢复
docker stop myrmidon && rm -rf data && tar xzf backup-2026-11-05.tar.gz && docker start myrmidon
```

**升级**：拿到新版本镜像包 → `docker load` → `docker rm -f myrmidon` → 用新 tag 重新执行 `./deploy.sh --skip-admin`（数据在 `data/` 不受影响）。
**回滚**：换回旧 tag 启动即可，数据结构向后兼容。

## 五、对外提供服务

默认只监听 `127.0.0.1`，外网访问不到。多人使用时请前置 Nginx 并启用 HTTPS，配置样例见《交付部署.md》第 4.3 节。若目标在内网，VPN 接入的三种方式见该文档第 6 章。

## 六、注意事项

| 事项 | 说明 |
|---|---|
| **架构** | 本包为 `linux/amd64`。ARM 服务器需用 `--platform linux/arm64` 重新构建，混用会报 `exec format error` |
| **root 运行** | 镜像内已设 `IS_SANDBOX=1`，root 下 Auto 可正常执行；若脱离镜像直接跑 console，需自行 `export IS_SANDBOX=1` |
| **安全边界** | 仅可在**书面授权**的目标上使用；首次登录后请立即修改初始密码，并为每位使用者分配独立账号 |
| **数据位置** | 任务数据、账号、日志、模型配置全在 `data/`，迁移/备份只需搬这个目录 |
| **工具链** | 控制台镜像只含编排与模型调用，不含 nmap/sqlmap/nuclei；需要实际执行工具时使用 Kali 底座镜像（源码包 `docker/Dockerfile`） |
| **容器隔离** | AI 执行的命令在容器内，**看不到宿主机**的 Docker、宿主路径与宿主工具。若任务需要宿主机能力，请挂载或改用 agent 镜像。实测中模型会如实报告"容器内无 docker"，属预期行为 |
