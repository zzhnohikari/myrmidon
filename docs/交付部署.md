# sapper 控制台 — 交付部署指南

面向客户现场部署。单容器即可跑通「网页控制台 + AI 编排」，不绑定任何比赛平台。

---

## 1. 架构

```
┌──────────────────────────────────────────────┐
│  控制台容器 (sapper-console)                  │
│  网页(8890) + 任务图谱 + Auto/跑分调度         │
│  └─ claude CLI（调用模型网关）                 │
│  /data  ← 挂载卷：任务根 / 账号 / 日志 / 配置   │
└──────────────────────────────────────────────┘
        │ 模型网关（LLM）        │ 靶标 / 比赛平台
        ▼                        ▼
   api.provider...          （内网 / VPN / 公网）
```

- 控制台和 AI 任务**同容器**（面板靠 `ps` 发现跑分进程，跨容器会看不到）。
- 需要真实渗透工具（nmap/pwntools/nuclei）时，把镜像换成 `docker/Dockerfile`（Kali 底座）那套，控制台代码相同，只是镜像更大（约 5.3GB）。

---

## 2. 快速开始

```bash
cd docker
cp .env.example .env          # 填模型网关 BASE_URL + TOKEN
mkdir -p data

# 1) 生成管理员账号（写入挂载卷）
docker compose run --rm --entrypoint python3 console \
  /app/lib/sapper.py console-user add admin \
  --role admin --password '换成强密码' --file /data/users.json

# 2) 启动
docker compose up -d --build

# 3) 打开 http://127.0.0.1:8890  → 登录 → 开始页
```

首次进入后：
1. 「设置 → 模型网关」填 BASE URL / TOKEN（或直接在 `.env` 里配）
2. 「设置 → 任务凭证」填比赛平台 token（若用 TSecBench / CTFd）
3. 「设置 → Auto 默认参数」把预算、步数、默认模型定好，客户就不用每次填

## 3. 账号与权限

```bash
# 新增只读客户账号，只能看到指定目录
docker compose exec console \
  sapper console-user add clientA --role viewer --roots 'client-a,client-b' \
      --password 'xxx' --file /data/users.json
docker compose restart console
```

| 角色 | 权限 |
|---|---|
| `admin` | 全部：建任务、跑 Auto、配置引擎/凭证、看所有目录 |
| `viewer` | 只读：只看到 `--roots` 授权目录的任务和图，看不到跑分/设置页 |
| （未配 users.json） | 开发模式：不鉴权，**只允许绑 127.0.0.1** |

隔离规则：目录级。每个客户一个根目录（侧栏「＋ 目录」可建），账号 `--roots` 填目录名。

**账号文件路径**：`console-user` 默认写 `~/.sapper/users.json`（容器内 HOME=`/data`，即
`/data/.sapper/users.json`）。控制台未显式给 `--users` 时会**自动加载**这个文件，容器入口
同时认 `/data/users.json`，两条路径都行——所以带 `--file /data/users.json` 和不带都能生效。

交付前确认鉴权真的生效（未登录必须 401，不是 200）：

```bash
curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8890/api/missions
# 期望 401；返回 200 说明还是开放模式，检查 users.json 是否落在容器认的路径
```

## 4. 平台接入（不绑定腾讯云）

| 平台 | 用法 |
|---|---|
| 腾讯 TSecBench | 设置里填 BASE_URL + token，平台选「TSecBench」 |
| CTFd / 自建 | 平台选「CTFd」，填地址 + 访问令牌 |
| 没有 API 的平台 | 用「渗透测试/其他任务」手工建任务，结果页复制 flag 手动提交 |
| 组委会给题目+flag 文件 | 平台选「本地离线」，在任务根放 `arena.json`（见 `docs/新平台接入.md`） |

新平台只要写一个 `lib/arena_<名字>.py`（5 个方法），详见 `docs/新平台接入.md`。

## 5. 数据与备份

`/data` 是唯一状态目录：

```
/data
├── roots/            每个子目录 = 一个任务根（客户/项目）
│   └── <root>/<task>/.sapper/   ← 任务图谱（JSON，人可读）
├── users.json        登录账号（pbkdf2 哈希）
├── engines.json      模型引擎配置
└── .sapper/console.json   平台凭证、默认参数（0600）
```

备份：`tar czf sapper-$(date +%F).tgz /data`（停容器或接受写入中备份）。
恢复：解包回 `/data` 后重启容器。

## 6. 放到公网（推荐做法）

不要直接 `-p 0.0.0.0:8890`。用 Nginx 反代 + HTTPS：

```nginx
server {
    listen 443 ssl;
    server_name sapper.example.com;
    ssl_certificate     /etc/letsencrypt/live/sapper.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/sapper.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8890;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 300s;
    }
}
```

要点：
- 容器端口仍绑 `127.0.0.1`，只让 Nginx 访问
- 一定要有 `users.json`（否则无鉴权）
- 建议再加一层 Nginx `auth_basic` 或 IP 白名单

---

## 7. VPN（靶场在内网时）

| 宿主 | 方案 |
|---|---|
| Linux | 容器加 `--cap-add NET_ADMIN --device /dev/net/tun`，容器内跑 openvpn；或直接 `network_mode: host` |
| macOS/Windows | Docker Desktop 不支持 host 网络继承宿主 VPN → 用 Linux VM 跑 Docker，或用 compose 里的 vpn sidecar |
| 最省事 | 靶场有公网入口时不走 VPN；或把控制台部署在能直连靶场的跳板机上 |

compose 里已给出 vpn sidecar 注释模板（`network_mode: service:vpn`）。

## 8. 运维

```bash
docker compose logs -f console          # 日志
docker compose exec console sapper console --help
docker compose restart console          # 改账号/配置后重启
docker compose pull && docker compose up -d --build   # 升级
```

健康检查：`GET /api/health` → `{"ok":true,"auth":true,"roots":N}`

资源参考：控制台本身占 200-400MB；每个并发 Auto/跑分 worker 另占 300-600MB（claude CLI 进程）。
3 并发建议给容器 4GB 内存上限。

---

## 9. 交付前检查清单

- [ ] `users.json` 已生成，默认口令已改
- [ ] 容器端口只绑 127.0.0.1，对外走 HTTPS 反代
- [ ] `.env` 里模型 key 是客户自己的，不是你的
- [ ] `/data` 有备份策略
- [ ] 「设置 → 引擎」里指向的 wrapper 脚本在镜像内存在（默认用环境变量即可，无需 wrapper）
- [ ] 客户账号是 `viewer` + 限定 `roots`
- [ ] 用 `viewer` 账号登录验证：看不到别人的目录、看不到设置页、不能建任务

## 10. 打包与分发镜像（离线交付）

客户环境常常不能连公网，或者你想给一个"开箱即用"的包。

### 10.1 构建控制台镜像

```bash
cd sapper-v2
docker build --platform linux/amd64 -f docker/Dockerfile.console -t myrmidon-console:1.0.0 .
```

产物约 1.25GB（解压后 418MB）。它包含：Python 3 + Node 22 + claude CLI + 控制台代码。

> **镜像内不含任何默认账号或密码**，首次部署必须用 `console-user add` 显式创建（或直接跑 `deploy.sh`）。

> **架构必须对齐客户机器**（实测踩过）：在 Apple Silicon 上不加 `--platform` 构建出的是
> `linux/arm64` 镜像，`docker load` 到 x86_64 云服务器上能成功，但一执行就
> `exec /usr/bin/python3: exec format error`。客户是 x86_64（绝大多数云主机）就用
> `linux/amd64`；客户是 ARM 就用 `linux/arm64`。构建后核对：
>
> ```bash
> docker image inspect myrmidon-console:1.0.0 --format '{{.Os}}/{{.Architecture}}'
> # 期望 linux/amd64
> ```

### 10.2 导出为 tar（拷贝给客户）

```bash
docker save myrmidon-console:1.0.0 | gzip > myrmidon-console-1.0.0.tar.gz
# 约 405MB（压缩后）
```

客户机器上：

```bash
docker load < myrmidon-console-1.0.0.tar.gz
docker images | grep myrmidon-console
# 再核一次架构，避免拿错包
docker image inspect myrmidon-console:1.0.0 --format '{{.Os}}/{{.Architecture}}'
```

### 10.3 用打包镜像启动（不需要 compose / 不需要构建）

```bash
mkdir -p /opt/myrmidon/data

# 1) 先生成账号（写入数据卷）
docker run --rm --entrypoint python3 \
  -v /opt/myrmidon/data:/data myrmidon-console:1.0.0-amd64 \
  /app/lib/sapper.py console-user add admin \
  --role admin --password '换成强密码' --file /data/users.json

# 2) 启动
docker run -d --name myrmidon --restart unless-stopped \
  -p 127.0.0.1:8890:8890 \
  -v /opt/myrmidon/data:/data \
  -e ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic \
  -e ANTHROPIC_AUTH_TOKEN=sk-你的key \
  myrmidon-console:1.0.0-amd64

# 3) 验证
curl -s http://127.0.0.1:8890/api/health
open http://127.0.0.1:8890     # 登录后进入
```

> 注意 `--entrypoint python3`：镜像的 ENTRYPOINT 是控制台启动脚本，跑一次性命令时要覆盖它。

### 10.4 推到镜像仓库（可选）

```bash
# 以 GitHub Container Registry 为例
docker tag myrmidon-console:1.0.0 ghcr.io/<你的用户名>/myrmidon-console:1.0.0
echo $GITHUB_TOKEN | docker login ghcr.io -u <你的用户名> --password-stdin
docker push ghcr.io/<你的用户名>/myrmidon-console:1.0.0
```

客户侧直接：

```bash
docker run -d --name myrmidon -p 127.0.0.1:8890:8890 \
  -v /opt/myrmidon/data:/data \
  -e ANTHROPIC_BASE_URL=... -e ANTHROPIC_AUTH_TOKEN=... \
  ghcr.io/<你的用户名>/myrmidon-console:1.0.0
```

### 10.5 打包清单（交付给客户的目录长这样）

```
myrmidon-1.0.0/
├── myrmidon-console-1.0.0.tar.gz      # 镜像
├── docker-compose.yml                  # 可选：用 compose 起
├── .env.example                        # 网关凭证模板
├── 使用手册.html                        # 图文操作手册（单文件，双击可看）
└── 交付部署.md                          # 本文件
```

客户三步：`docker load` → 生成账号 → `docker run`。

### 10.6 升级与回滚

- 升级：导出新版本 tar → `docker load` → `docker rm -f myrmidon` → 用新 tag `docker run`
- 数据不丢：所有状态都在 `/data`，容器本身无状态
- 回滚：换回旧 tag 启动即可（数据结构向后兼容）

以下信息取自实际构建产物，可直接核对。**已按 linux/amd64 构建**（客户 x86_64 云主机直接可用）：

| 平台 | `linux/amd64` |
| image id | `sha256:085ef36c175e7db9ffc043c3a1bfc586c54c81661d396fd92458844cce527a04` |
| 镜像大小 | 423,083,562 字节（约 404MB） |
| 导出文件 | `dist/myrmidon-console-1.0.0-amd64.tar.gz` |
| sha256 | `57c8996a0cec087a78650b96a5fe2e69eb82eb7480c0062cc54931f70e31792f` |

> `dist/` 不入库（体积原因），构建机上传或拷 U 盘交付。客户 `docker load` 后核对：
> `docker image inspect myrmidon-console:1.0.0-amd64 --format '{{.Os}}/{{.Architecture}}'`
> 应为 `linux/amd64`。ARM 客户需用 `--platform linux/arm64` 另建一份，两者不可混用。

**实测记录（2026-11-05，腾讯云北京竞价 SA3.MEDIUM4 / Ubuntu 22.04）**：`docker load` 11s →
建账号 → `docker run` → 容器 healthy、未登录 401、登录 200、建任务成功 →
真跑一次 Auto（DeepSeek）：两轮推理、目标完成、5 条情报落库。

> **root 运行注意**：claude CLI 拒绝 root 直接用 `--dangerously-skip-permissions`（Auto 必需）。
> 镜像里已内置 `IS_SANDBOX=1` 放行；**裸机以 root 跑 console 时**要自己
> `export IS_SANDBOX=1`（或用普通用户运行），否则 Auto 每步都会报
> `dangerously-skip-permissions cannot be used with root`。

### 10.8 需要渗透工具链时

控制台镜像是"大脑"，不含 nmap/pwntools/nuclei。若要 AI 真正执行工具：

```bash
docker build -f docker/Dockerfile -t myrmidon-agent:1.0.0 .   # Kali 底座，约 5.3GB
```

并把 `-p` 换成该镜像；控制台代码一致，只是镜像更大。
